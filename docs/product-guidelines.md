# 产品规范

本规范描述 wish-creator 的产品定位、核心语义和用户旅程。涉及产品概念、业务边界、交互或文案时，应以此为基础判断。

## 产品定位

项目英文名为 **wish-creator**，中文名为 **许愿池**。

许愿池是面向普通用户的 AI 应用创作平台。用户不需要先学习编程、设计或部署，只需描述想实现的需求——也就是“愿望”——许愿池 Agent 便与用户一起澄清需求、创建网页应用、展示实时预览，并将成果发布为可分享的线上地址。

产品目标是：

> 让每个人都能把一个愿望，一步步变成可交互、可使用、可分享的作品。

衡量方案时，不要只判断“是否生成了代码”，还要判断用户是否能够理解进度、试用结果、持续修改并完成发布。

## 核心用户旅程

1. **许愿**：用户用自然语言描述目标、受众和期待效果。
2. **澄清**：许愿池 Agent 识别信息缺口，只追问对成品有实质影响的内容，并为其余细节提供合理默认值。
3. **生成**：将愿望转化为可运行的网页应用，同时让用户感知当前进度。
4. **预览**：生成过程中逐步展示可操作的效果，让用户能够直接试用和验证。
5. **修改**：用户持续提出反馈，许愿池 Agent 在现有作品上增量修改，并通过预览反复验证。
6. **完成与发布**：完成最终检查，发布为稳定、可访问、可分享的线上地址。

## 典型场景

一位中学物理老师希望制作可交互的小实验，用于演示光的折射定律，并比较同种色光在不同介质中的表现。

许愿池 Agent 应先理解教学目标、使用对象和关键交互，只确认会实质影响成品的细节；随后生成应用，并持续提供可见进度和可操作预览，最终帮助用户获得公开链接。

## 当前阶段与业务边界

当前代码库是全栈 AI Application 基线，现有 TODO CRUD 只是占位示例，不是许愿池的领域模型。

后续产品能力应围绕以下概念逐步澄清边界：

- 愿望
- 对话
- 生成过程
- 作品
- 预览
- 发布

这些名称描述的是当前产品方向，不代表对应模块、接口或状态机已经存在。实现前应先验证代码现状，并澄清当前需求真正涉及的概念；不要仅凭这份列表预先设计全部系统。
